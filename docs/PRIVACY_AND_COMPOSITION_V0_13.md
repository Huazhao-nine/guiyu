# v0.13 同一任务中的工具协作与分享脱敏

归屿把资料工具、本地计算和日期核对放入同一份计划。可以先从工作区找到资料，再使用当前原文、筛选后的表格和已有工具结果计算，最后写成文稿并核对交付是否齐全。执行中可在原资料范围内补充必要步骤，用户关闭的工具不会重新打开；原文发生变化仍会停止并要求重新规划。

## 可以怎样使用

“根据活动方案计算筹备费用和剩余预算，核对活动提前7天的确认日期，再写一份简短说明。”

归屿先显示可调整的计划，确认开始后在本机依次执行。计算和日期步骤只处理各自要求，完整目标作为共同条件保留。计算参数只能来自用户、当前授权资料和核对过的结果；有行筛选时，计算步骤不能从被排除的原文记录取得新金额。步骤无法核对完成时会停下，不能直接跳过错误去写作。

计划仍最多8步，初始模型规划最多6步，执行反馈最多补充2步，最终漏交付最多补做1项；没有新增任意代码、命令行、联网或未授权文件工具。每个计算/日期步骤内部仍有限次工具调用与交付检查。若最后发现漏算，先补核对，再重新生成依赖它的文稿；达到原有修订上限时明确保留未完成状态。同一算式中的中间金额也由受限计算器精确复核，保守区分币种与数量；不会因模型写出一个中间值就直接承认为事实。已经完成的结果会保存，失败后可查看原因再继续。日历工具按公历日历天计算，不推断法定工作日和调休。

## 分享前脱敏

打开“隐私空间”的“分享前，先留住隐私”，粘贴文字或点击“带入当前结果”，再点击“预览脱敏”。也可先试用虚构文本。默认使用本地规则，无需下载模型，也不需要等待对话模型加载。

- 密钥与密码：识别常见API Key、Token、密码赋值、私钥块和自定义密钥前缀。
- 联系方式与证件：邮箱、国内手机号、校验通过的18位身份证号，以及带银行卡/卡号说明且通过Luhn校验的16–19位卡号。
- 自定义词：额外遮盖姓名、地址或代号，忽略大小写；可以填写保留原样的完整识别值。

只复制或保存当前脱敏文本，不自动还原敏感值。相同值在一次预览中使用同一占位符；每次预览重新生成占位符标识。重叠识别会遮盖整个区间，避免只遮到密钥的一部分。更改原文或设置会使旧预览失效，离开页面清除本次内容。设置与预览不写入工作历史，不保存还原映射。保存副本拒绝覆盖已有文件，原始文件保持不变。

这是一项分享前的辅助检查。规则没有上下文识别人名和地址的能力，也不覆盖所有国际电话号码、证件和密钥格式；需要遮盖的姓名、地址请填自定义词。保留名单可能让敏感值保持原样。普通金额与日期默认保留，避免改变办公内容的含义。归屿的资料、检索和推理仍全部本地，脱敏不是改用云端模型的入口。

## 参考产品和专用模型

借鉴magpie设置中的分类开关、自定义词、保留名单与本机试用体验。归屿目前不增加厂商请求拦截、云端占位符还原、订阅账号读取或遥测。分享副本与本地任务使用的原始事实分开，避免把金额、日期和身份关系提前遮掉导致计算或写作失真。

| 方案 | 核实到的信息 | 本轮结论 |
| --- | --- | --- |
| 规则识别 | 无模型权重；明确的格式与自定义字面词 | 已接入原生分享预览，无额外推理依赖 |
| AstrLink Guard | Apache-2.0；37M参数；固定v0.1.3的INT8图、权重、tokenizer与config合计约39MB；CPU运行 | 已下载官方文件并校验SHA256，用6项虚构样本禁网实测，适合作为后续独立“隐私增强组件” |
| OpenAI Privacy Filter | Apache-2.0；1.5B总参数、50M激活参数；本地token分类，8类隐私标签、长文本支持 | 已核对官方说明；本轮未下载或运行，尚不能比较中文质量或实际内存。“1.6GB”取决于具体转换版本，不等于所有格式的体积 |

AstrLink的6项开发样本含中英文联系方式与密钥、普通办公数字、无隐私代码、个人日期及跨窗口文本。13个预期敏感片段均覆盖，但普通活动日期2026-11-06被误标为私人日期，另一无隐私代码样本没有检测结果。跨窗口示例存在重复和局部邮箱片段，覆盖统计按区间并集计算。CPU进程RSS峰值约0.209GB，含运行时，不是模型文件大小或与9B同时运行的整机内存。推理适配使用模型卡的近似argmax BIO示例及滑窗，不是供应商完整清理/解码实现。这些是固定开发样本，不是泛化准确率。

专用模型权重和ONNX Runtime仅用于项目私有研究环境，没有安装进正常应用，没有自动下载或切换检测器。原生界面本轮使用的仍是规则。可在已准备的项目虚拟环境运行 `uv pip install --python .venv/bin/python onnxruntime==1.31.1` 复核研究环境，不需要将该依赖加进普通应用。生产接入前需要明确类别选择，尤其是日期、账号与URL；保留规则兜底、可查看的预览、加载失败提示和中文误检/漏检验收。隐私模型应与日常对话模型分开管理，并按需加载、及时释放，以保持16GB基础配置。

官方来源（核对日期2026-10-28）：

- [AstrLink Guard官网](https://astrlink.com/en/guard/)
- [AstrLink Guard官方模型卡与文件校验](https://huggingface.co/QuantumNous/astrlink-guard)
- [OpenAI Privacy Filter官方介绍](https://openai.com/index/introducing-openai-privacy-filter/)
- [OpenAI官方模型卡](https://huggingface.co/openai/privacy-filter)

模型研究复核入口是 `scripts/evaluate_privacy_guard.py`，ONNX Runtime1.31.1仅安装在本项目虚拟环境。`--download`仅获取固定官方公开模型文件，不接受文本；普通运行先进入禁止网络的沙箱，再加载CPU模型。报告为 `qa/v0.13-privacy-guard-evaluation.json`，权重不进入发布包。

混合任务固定用例为 `fixtures/composed/tasks.json`，入口为 `scripts/check_composed.py`。开发机仍为M5 32GB，使用既有16GB运行策略；不替代16GB设备、非技术用户研究或独立安全审计。
