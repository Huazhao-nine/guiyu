# v0.18：根据真实结果逐步工作

本轮开发协议在首次实机运行前确定。先修复v0.17的已知失败，再冻结后端，对完整回归与新的工作簿变体执行一次验收；保留原始分数、失败、源哈希、每次模型调用与工具动作。新的工作簿变体不用于本版最终验收后的再调试，不将多次运行中通过的案例拼成一次全通过。

应用的新自动工作簿请求使用增量工具协议。模型一次选择一个已定义工具，收到实际字段、单位、记录数和错误后继续决定。各个结果有独立名称，分组结果不会覆盖明细；交付可以同时引用明细、多个汇总，再写作。重启后的旧版计划保留原执行协议，不迁移或篡改已有结果。

字段使用本轮可验证的编号，用户界面仍显示原始或单位统一后的中文/原语言标题。数值单元格先按显式单位、再按表头单位统一到元、USD、克或分钟等基础单位。百分比保留比例语义，布尔值与文字分类分开。显示单位在最后转换，计算不依赖模型猜测倍率；不同货币不猜汇率。编号保留文字，非数值内容与单位冲突保留原文并明确不参与直接计算。公式只解析字段编号、常数与四则运算的受限语法，不执行Python或任意代码。

最多16个动作、4次工具错误和2次明确漏项补做；中间结果在本轮内保留。单个结构化动作使用确定性采样和较小输出预算。输入仍为最多5,000条合并记录、40列；文件、工作表、候选区和索引读取限制继续适用。全部处理本地，生成新副本，原文件修改仍需预览和独立确认。16GB是设计基础，实际测试机M5 32GB，不宣称16GB实机验收。

除了数值来源检查，新流程也检查可以从工具参数严格确认的错误：同一字段在“且”中同时等于和不等于一个值、明确去重键被加入其他分组维度、带字段名的明确数值边界被改成另一种比较方式，以及整批总计被逐项分组替代。文字约束绑定只在原话与真实字段能明确对应时生效；它不等于已经理解任意自然语言。无法识别的业务同义词仍由本地模型解释、复核，可能失败。

每次成功操作会向本地模型反馈真实字段、记录数及最多三条简短结果。模型生成的额外数字、文件路径和文稿正文不能直接成为交付事实；表格执行结果要再次回放核对，Word中的数值、汇总与记录顺序由已核对结果填入。明细预览与Excel/CSV导出进行一致性检查，汇总保留可追溯的来源行。

数据操作具备可交付的视图、且已出现明确要求的操作种类时，程序会主动提出一次交付候选，随后仍进行独立的目标复核、输出字段绑定、确定性回放和导出检查。候选并不代表语义正确，也不会跳过漏项核对。未通过时继续工具协作；同一图状态不会不停触发自动交付。这样减少“数据已经算好、模型却继续重做”的循环。

对话中的“其他要求不变”可以继承本线程的明确交付约定，包括明细、附加汇总、输出字段和Word。明确要求换成新交付形式或取消Word时，以当前请求为准。放宽筛选条件仍从原始完整表重算；不能只在旧的较小结果中查找。恢复历史记录不会自动重新执行。

同范围追问会保存上轮已经执行并核对的行内计算关系。当新条件引用原表没有的派生列时，程序按需重建其依赖，保留每一步新视图，并在交付时重新回放。它只复用逐行四则公式，不把旧筛选、去重或分组后的记录当成完整原表，也不把汇总公式套到原始行上。资料快照或所选工作表改变时不继承这些关系；新的明确计算优先。计算关系最多16项，依赖最多6层，实际数据操作仍有16项上限。

模型输出若只有JSON标点错误，可以在本机单独修订一次；修订前后按顺序逐个核对键、字符串、数字、布尔值和null，任何字段或数值改变都拒绝。无法确定原始字符串边界时不猜测。每个任务最多三次这种格式修订，之后仍受原来的错误与动作上限控制。格式修订不代替工具参数、数据范围、单位、完整性和回放检查。

百分比条件允许明确对应用户百分比的等价参数。例如用户已指定63%，工具的63或0.63可统一为63%；若同一参数能对应两个不同百分比，停止猜测尺度。常见的`arguments`/`parameters`对象封装可以规范化为同一个受限工具动作，冲突参数和未定义参数继续拒绝。交付约定只要求小型JSON，格式错误有一次本地重试；缺少“最佳”等业务判断标准时保留澄清。

工具参数有明确白名单，额外的`and`、`write`等字段不能被静默忽略。同一JSON对象的重复参数会拒绝；修订反馈包含具体参数问题及有长度上限的失败动作，模型可以拆开计算或改正条件，已成功的视图保留。所有错误反馈只在本机使用。

程序读取模型返回的第一个完整工具对象，模型附带的自报结果或`input_status`不能成为数据事实，串接多个工具对象也会拒绝。数据中的真实列名可用作数值/日期字段比较引用；公式末尾若遗漏字段引用的关闭括号，只有剩余文本能够唯一对应真实字段时才补全。不会用猜测的字段名或数字修订表达式。

用户明确排除某个实际文本值，且该值只能对应一个真实字段时，会形成来源约束。交付时检查明细与所有汇总的来源行，遗漏排除条件会退回补做；没有依据的隐含语义仍由模型理解、复核。新一轮明确把该值纳入时，可以覆盖沿用的排除约定。

同一任务内也可复用已核对的行内计算。对汇总结果重复提出来源筛选时，程序只在前序“且”条件能够严格保证该条件的情况下认定已满足，绝不把“或”的分支当成事实。排序或选列若指错输入，可以复用来源行集合相同、且唯一含所需字段的已有视图；候选不唯一或来源不同就不自动跳转。

等价条件可以规范化，例如外层`and`与`where`合并为同一条件树；每项条件都保留，语义冲突则拒绝。不能理解的参数继续停止处理。“不去重”“不要重新计算”等明确否定不会计为待办工具，执行前也会检查限制。输出视图类型只是模型提示，不能阻止真实明细交付，明确要求明细和汇总时仍须两者都保留。

结构准备结果会进入规划及复核：实际选定输入、完整记录数、已对齐与已追加状态、已排除汇总行及单位处理说明。宽表不同期间各占一列时，选择统计列与按行筛选有不同含义；复核需要同时看到原始结构和实际条件，不能仅检查文件是否生成。

界面沿用对话、进度和结果卡。处理过程默认显示最近三项，展开才显示全部记录；不要求用户为每个数据操作选择工具。

验证同时覆盖工具正确性、实际本地模型完成质量、文件导出与原生对话流程。固定案例只提供开发与回归证据；改变表头/顺序/数值/单位/条件表达后的结果和输入变化一致，才算相应适应检查通过。任意跨表连接、宏、扫描件、无限上下文和任意电脑控制仍不属于本轮。
