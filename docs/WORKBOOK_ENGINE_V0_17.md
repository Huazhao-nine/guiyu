# v0.17：先理解表结构，再编排数据操作

归屿的自动工作簿任务现在采用独立的数据流程。用户直接交代目标，应用先检查授权范围内的工作表、表头、合并单元格、字段类型和空值，再选择数据区域、生成操作计划、执行并核对副本。用户不必先选“筛选”或“统计”。显式使用旧筛选面板、旧工具接口及分享脱敏流程仍保留各自的边界。

## 结构理解

- Excel与CSV；工作表可以属于不同业务，不再要求所有候选表都具有同一表头。
- 模型查看工作表概要、前部实际行、末部行与合并范围，选择真实表头位置；支持连续1–3行表头。多级表头展开成“上层 / 下层”，例如“10月 / 实际（元）”。
- 同字段集合、不同列顺序的多表可以纵向追加；不会默认做笛卡尔积或猜测跨表关联。
- 空表、说明页和其他业务的表可在结构选择时排除。首个非空值恰为“合计、总计、小计”等的行可明确作为汇总行排除，并在结果中说明具体行号。
- 空白与零值分开处理。编码、学号、电话号码等使用文字；日期保留真实年月日；数值比较和统计采用Decimal，识别万元与百分比表头单位。

## 可以组合的操作

模型只能输出已定义的结构化操作，不能提供Python、SQL、Shell、Excel公式或任意文件路径。执行程序根据真实字段验证参数，逐行处理原始记录：

| 操作 | 用途 |
| --- | --- |
| filter | 嵌套的且、或、非；文字、集合、数值、完整日期与空白条件 |
| derive | 根据已有字段计算新列，支持加减乘除与百分比显示 |
| group | 按字段分组，求和、均值、最值、计行、非空计数或唯一值计数 |
| summary | 保留明细，同时附加合计和计数，避免为了汇总而丢掉名单或明细 |
| sort | 最多四个排序字段，明确数字、日期或文字类型；空白始终放最后 |
| limit | 截取前几条或指定起点；不会自行假定排名方向 |
| select | 按要求选择并排列输出字段 |
| distinct | 按指定字段去重，保留首次记录并保留原始行来源 |

例如“找出库存低于安全库存的物料，计算补货成本，取成本最高的几项，再附合计”会组合派生列、条件、排序、截取和汇总。程序处理数值，模型不直接生成结果行。

## 连续追问与纠错

资料快照未变化且没有切换工作表时，沿用已核对的表结构，减少重复规划。上轮记录保存了源文件快照、选表和表头、操作程序与实际结果。新要求可以从原始数据重算，也可以只在上轮结果内继续处理。改变门槛、保留其他条件，或从明细改为部门汇总时，模型根据当前目标重新编排；资料有变化时不能沿用旧结果冒充新数据。

字段不存在、类型不匹配、混合货币、除以零、不可读取公式缓存、结构不兼容等，会产生明确的工具反馈。先保留实际计划，通过带原始位置的操作替换局部修正，每次最多六处；局部修订仍失败时仅允许一次完整重新规划，重新执行和复核仍在原权限范围内。数值阈值与常数需来自当前或仍有效的上轮要求，防止自行增加条件。没有“优秀”“最好”等业务标准时，应请求标准，不以常识替用户选指标。放宽筛选导致条数增加，属于已授权的重算，无须再次确认。

## 交付与隐私

应用提供最多20行的对话预览、Excel和CSV副本。Excel包含主结果、可选汇总页与来源核对页；来源核对页记录结果行对应的源文件、工作表和原始行。CSV仅包含主结果。Excel保留编码文字，金额等写为数值、日期写为日期、百分比写为比例与显示格式，便于后续计算；超过Excel安全数值精度的长数字保留文本，不冒险舍入。应用回读两种副本的单元格，核对是否与程序结果一致；附加汇总页也单独核对。

明确要求写作时，模型选择本轮已核对的事实块，程序填入金额、日期、记录顺序及汇总，生成数据说明或邮件框架；模型给出的自由草稿不会直接作为事实指令。当前优先支持事实型数据文稿，不把它等同于任意深入分析。文稿展示最多200条明细，完整结果保存在Excel与CSV中。不会重新把筛选外的原始记录作为依据。原始材料与结果副本仍保留在本机，工作记录也属于本机私有内容；普通工作簿导出并不是脱敏导出，分享私人资料仍须使用独立的“可分享版本”流程。

全部推理、结构检查、数据操作与导出在本地执行。原文件不改动；文件整理或其他原文件修改仍须预览并另行确认。

## 资源边界

16GB Apple Silicon仍是基础配置，默认模型选择不变。新数据执行层每次最多5,000条合并明细、40列、40个候选表区域、每个Excel最多30张工作表；总检查不超过40万个单元格。最多10个操作，条件深度和数量均受限。工作区索引及模型上下文还有各自的完整读取限制；超过任一范围时提示缩小范围。

本版支持常见矩形数据区域与连续多级表头。任意报表排版、透视表重建、宏、跨表关联、跨文件复杂连接及任意脚本执行尚不在本轮范围。实际测试机为M5 32GB，不能据此声称已完成16GB实机验收。

## 验证

`fixtures/workbook_general/tasks.json`固定了采购、销售、库存、报名四类资料的12项任务及预期记录，包含多轮修改、两层表头、派生字段、复杂条件、合并去重、明细与汇总、Word交付及缺少业务标准的澄清。`scripts/check_workbook_agent.py`串行使用已安装本地模型和BGE，在禁网子进程、独立虚构资料与数据目录中执行，保留失败、过程与源哈希。

最终完整矩阵10/12，补充两个固定新结构变体0/2。复杂文稿联合交付、多表去重分组、万元单位与英文表头变体仍有模型规划失败。执行器支持上述工具，并不意味着模型已经能稳定编排任意组合；详细结果与耗时在证据报告中逐项保留。

单元测试包括数值/日期/单位、条件树、排序与空白、来源行、结构选择、计划纠错、上轮结果沿用、原件快照、导出内容和不确定任务不猜测等。具体实测结果以`qa/v0.17-*-workbook-report.json`和`docs/EVIDENCE.md`为准；开发回归不是通用成功率或独立用户研究。

复核与修订共享程序已经完成的表头对齐、纵向追加与真实行数，避免重复安排预处理。工具错误包含原始操作编号和名称，最多两次局部修订围绕具体失败位置进行。仍失败时，依据原始完整目标、真实结构与错误原因重新规划一次简洁方案，再走同样的字段、数值来源、条件与导出检查；次数耗尽则停止，不交付猜测数据。首次去重沿用输入顺序，未获用户要求不会为此引入日期排序或类型转换。
