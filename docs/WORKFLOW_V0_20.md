# v0.20 工作簿修订与可靠交付

以16GB Apple Silicon为设计基础，实际开发设备为M5 32GB。既有Qwen3.5 9B与本地BGE用于规划与检索，全部资料和推理留在本机，不添加在线回退。原文件修改继续先预览与独立确认。

## 参数与条件修正

工具只接受受限结构，不执行生成的代码、SQL或表达式字符串。常见参数封装与视图引用按契约归一化；逻辑选择词必须归属条件树，不能丢弃日期、金额或状态子条件。对缺失括号、逗号和冒号的JSON，程序按语法补齐标点，原键、字符串、数字、布尔和null的顺序必须一致；缺少键值、重复键或含义不明确则停止。

模型修正仅接收失败动作、具体错误、真实字段、各视图的角色和允许参数。正确的中间结果保留，减少重复整轮规划。金额下限、明确ISO日期范围与唯一实际分类等可严格从用户原话确定的遗漏，程序有限补齐过滤，并回放依赖图更新明细与所有关联汇总。每轮最多4次此类修正，不能增加原话没有的业务判断或去重规则。

交付还沿最终结果的实际依赖检查明确去重键，防止“做过去重，却回到去重前的数据汇总”。若同一输入上已有唯一、已验证的正确去重步骤，可重新连接这个依赖并重算后续汇总、排序与文稿；输入范围不同或多个候选则不自动选择。来源追踪会合并重复行的来源编号，因此不以来源编号数量代替是否实际使用去重结果的证明。

## 交付列与日期

输出字段数量修饰词单独处理。“小组、人数、累计工时三列”中的三列不是字段名；数量与实际字段清单不一致时不静默删列。需要语义对应时，在真实列集合内做一对一映射，失败仅局部重试一次，并缓存当前计划内已验证映射。字段映射留在已核对记录中，供后续短追问复用。未输出的真实源字段，其显示格式不影响副本；未知字段依然拒绝。

字段优先按完整实际名称匹配，仅在唯一时容忍空格差异；单位、上级表头与列名仍参与区分。若去空格后出现多个候选，要求更精确的列名。“排除某期间”的列范围误用会在解析条件值之前反馈，模型可从失败位置改用计算、汇总或选列工具，已核对数据不变。明确针对该列值的行筛选仍可正常执行。

日历日期统一为ISO文本，预览、CSV和可编辑Excel日期一致。午夜时间可视为日历日期；带有效时刻或时区的时间戳保留原文作为文字，避免导出时丢失时间。日期条件按日历日比较，不推断工作日、节假日或时区转换。

## 简短追问

明确修改比较条件或放宽/收紧现有边界时，程序从原话读取值和单位，依据保存的字段对应关系和已验证边界决定修改位置。无歧义时无需再调用模型生成工具计划；其余条件、排序、明细、汇总和写作约定保留，并从同一完整来源重算。汇总指标的修改在分组之后处理，不能误作用于同名原始列。不同字段、多个候选边界或新业务要求仍走完整规划。

取消Word与取消写作分开理解：“其他不变，不要Word”可保留说明的Markdown；“只需要表格，不写文稿”不生成文稿。普通聊天与资料父任务分别跟踪；对话层将已判断的沿用范围显式传给索引，避免短追问再次按关键词检索而丢失上下文。实际文件发生变化时重新检查快照，明确换文件时不复用旧范围，不要求用户重选文件来返回原资料。

## 验证范围

v0.19的全部输入与失败已成为已知开发资料，旧报告保持。本轮先完成完整回归、单位/表头变体、适应与对话链及前版新表任务，保留这份修订前矩阵。发现去重依赖被绕过后，在最终代码上重点复测四项受影响的去重与汇总任务，再运行2份新工作簿的4项首次任务和完整原生对话链；修订前矩阵不算成最终代码的完整回归。新输入和预期结果在首次运行前固定，不根据首次新任务结果修改本版代码。结果见`qa/v0.20-evaluation.json`，原生对话与副本核对见`qa/v0.20-native-report.json`，完整证据见`docs/EVIDENCE.md`。

有明确5000条合并明细、40列和16次数据动作上限。可严格识别的条件校验不等于完整理解任意业务；未支持关系连接、宏和扫描件，不保证所有新表都完成。16GB是设计基础，M5 32GB测量不能代替16GB真机验收。

首次新表验证之后，工作簿引擎没有继续修订；原生检索衔接单独修正并通过527项Python检查与原生链复验，源文件差异另见`qa/v0.20/retrieval-context-update.json`。原生Word数字与副本正确仍可能伴随标题偏题，完整口径在证据报告中单列。
