# 归屿 0.26 通用办公迭代

本版继续使用Qwen3.6 35B A3B MLX 4bit，以Apple Silicon 32 GB为基础。重点是处理真实表格结构与连续任务中的依赖，所有资料、检索、推理、校验和文稿生成均在本机。原文件修改仍需预览及单独确认。

## 可以直接体验的工作

打开新版后选择“体验办公资料”，会在独立文件夹建立三份虚构填报工作簿和两份活动文字。再次打开会复用这个示例工作区，避免重复复制。卡片仅用于填入目标，用户仍可自由描述、组合和追问。

- 台账：组合月份、备注、空值与数值条件，输出逐条明细、合计、条数和Word。
- 报价：使用嵌套且／或条件，在结果副本中重算已有金额列，保留原文件。
- 服务记录：理解不同表头与单位，先按原始首次记录去重，再筛选、统计和换算展示单位。
- 活动资料：同时找到方案与变更记录，按最新内容计算预算与日期，保留付款状态，交付Word。

可继续说“已经用完的先去掉，其他规则和输出列不变，这次只要表格”，或“那累计工时至少2小时的组呢”。这些目标仍由模型安排工具，程序只补齐可以从原话与已核对结果证明的约束和依赖。

## 这次修改的机制

1. **错误步骤可以回退。** 数值和日期区间会检查同一“且”中的矛盾，也检查仍有效的前序筛选。错误反馈指出应退回的已有视图；不会在错误子集上不断追加筛选。或／非条件不被摊平成且，重算和分组会隔开不再有效的旧字段事实。
2. **区分明细与汇总。** 上轮已核对的分组结果可以直接进一步筛选。明确限制“累计值达标的组”时，不能先用同名的单条记录数值过滤。来源快照、上轮计划回放和结果指纹仍需一致。
3. **延续交付依赖。** 追问保留统计口径时沿用原来的统计定义，对当前筛选明细重新计算；不复用旧合计的数值。工具重复成功不会再被当作新的进展。
4. **支持明确重算已有列。** 只有用户明确说“重算／重新计算”并对应实际数值列，才允许在结果副本里替换该列。单位、公式、字段与原话需通过校验，原始视图保留，重复相同步骤复用已计算结果。
5. **单位展示与计算分开。** 支持“小时、元、kg、万元”等并列展示要求，内部仍使用统一基础单位。不会为了展示重复除以换算系数。
6. **原生Word清单逐行复制。** 请求中的两个实际表头能唯一指向一张原生表时，直接选表、复制全部行及零值；其他情况由模型选择真实表与字段。文稿中的完整清单由已提取单元格填入，避免生成时漏条目。
7. **保留正确的文档事实范围。** 已证明完整且未筛选的原生表格，允许同一文档段落里的预算等事实继续作为依据。筛过行、投影后不能借此恢复被排除的原文金额。
8. **兼容公开表格的空公式结果。** 只接受OOXML明确声明为字符串的空公式缓存；缺失数值缓存仍报错，不猜结果，也不执行公式代码。
9. **检索合并简称。** 对“方案和变更记录”等并列简称，在现有授权路径中寻找唯一对应文件；独立检索可累积相关资料，显式“其中／这些”筛选继续缩小当前范围。
10. **追问先解释新增要求。** 先由本地模型把本次追加目标映射到已核对结果。缺少明细日期等字段时，解释缩小范围的意图，再回原始明细继续处理，不强行在汇总里找缺失字段。每步仍经过普通类型、参数、数值依据和最终交付检查。
11. **交付指令与列清单分开。** “生成Word”等另一个交付要求、排位限制和已证明执行的日期条件不会被当作输出列；真正的同名字段仍可以选择，未知列继续报错。检查不依赖某个工作簿名或测试答案。
12. **Word版式复核。** A4、合理页边距和段距、黑色标题、表格边框与重复表头，让正文、明细、合计和资料来源自然衔接，减少单独空页。导出不改写已经核对的正文与单元格。

## 验证方法与范围

新材料包含公开高校的台账、报价版式和公开需求Word，以及虚构的服务、培训、配送和活动资料。输入与13个目标的预期值在模型首次执行前冻结。8项用于开发，另5项涉及两份在开发期间未索引、未交给模型的文件。原始公开Word不随包分发，重放时按固定URL和SHA256准备。

首次8项只有1项完整通过。后续分阶段复测与确认成绩见 `qa/v0.26/evaluation.json`，各阶段报告均保留；复测不替代首次成绩。所有任务经过实际路由、检索、模型规划、工具与导出检查。短追问还按原生客户端既有规则保留来源链，报告记录该客户端规则的源码哈希。

两份保留资料的首次主任务被交付列解析阻断，三条后续没有执行，总体0/5。修正后再测属于已知任务复测。之后额外新建并冻结支持日志和工位安排文字，首次2/3：工作簿统计和排位追问通过，含最新通知与可退押金的文字任务仍未完整核对成功。相关失败未删除，也未生成声称已核对的最终Word。这是尚待改进的版本事实协调问题。

工作簿导出按逐值预期、输出列、预览、Excel、CSV和汇总检查；Word检查数字、日期、条件与设备清单，并另行渲染查看。程序检查使用不同于模型评测的示例数据。实际测量设备是M5 32 GB；模型进程与MLX内存指标重叠，不能相加或称为整机内存。

这些仍是开发者组织的有限办公任务，不能代表任意未知资料的成功率。任意跨表关联、扫描件OCR、未知货币汇率、任意代码与系统操作仍不在开放范围。复杂目标可能需要澄清或遇到未完成交付；界面会保留可检查的结果和具体问题。

## 重建与复现

```sh
zsh scripts/build_model_demo_v26.sh
python -m unittest discover -s tests -q
zsh scripts/check_native.sh
python scripts/prepare_public_office_v26.py --restore-public-document
"$HOME/Library/Application Support/GuiyuRuntime/python/bin/python" scripts/check_office_novel_v26.py --group development --label local-development
"$HOME/Library/Application Support/GuiyuRuntime/python/bin/python" scripts/check_office_novel_v26.py --group confirmation --label local-confirmation
```

模型任务串行运行，每次生成独立轨迹和报告，脚本内部禁止网络。`--group confirmation`重跑属于已知任务复测，不能再次称为首次确认。源码包含首次与中间后端快照及最初评测器，支持在独立目录回放；较新的日期检查额外要求同时出现变更后的活动日和确认日，原始首次总体成绩不变。
